# Feeder Remote Worker

별도 Linux 서버에서 Rclone 소스 리모트 → 목적지 리모트 복사를 실행하는 Feeder 기본 이송 핸들러용 서비스입니다.

설치, 토큰 등록, 접속 테스트, 프로필 설정, 업데이트, 장애 대응과 API 사용법은 [Feeder README의 원격 워커 매뉴얼](https://github.com/golmog/feeder#원격-워커-설정)에 통합되어 있습니다.

설치 프로그램은 기존 Rclone 실행 파일과 인증 설정을 교체하지 않습니다. 설치 완료 시 표시되는 주소와 토큰을 Feeder에 등록하세요.

워커 0.11.0부터 새 작업은 Feeder의 **Rclone 추가 옵션** 전체 인자 배열을 전달받습니다. 공란 기본값은 `--drive-chunk-size 256M --timeout 60m`이고, 다른 값을 입력하면 이 기본값은 자동 합산되지 않습니다. `--transfers`는 Feeder 전용 파일 동시 전송 설정이 우선합니다. 실제 복사에 명시하지 않은 옵션은 설치된 Rclone 기본값을 따르며, 사전 목록 조회 전용 제한 시간·필터·재시도 정책은 유지합니다.

워커 0.12.0의 새 작업 API는 `rclone_extra_args` 문자열 배열(옵션이 없으면 `[]`)과 현재 Feeder의 `session_id`가 필수입니다. 추가 옵션의 순서·값이 다르면 동일 `job_id`에 HTTP 409를 반환합니다. 구형 개별 청크·타임아웃·버퍼 필드는 받지 않습니다. rclone 실행 파일·명령(`copy`)·인증 설정·소스/목적지는 워커가 별도로 관리하고, 사용자 추가 인자는 쉘 없이 인자 배열로만 전달합니다.

FF/Feeder가 새로 시작하면 새 실행 세션을 저장합니다. 첫 원격 등록 전에 이전 주소의 작업까지 조회하여 실행 종료·사용량 정산·임시 경로 복구를 확인한 뒤 `POST /api/v1/session/reset`에 `{"session_id":"<32자리 UUID hex>"}`를 보냅니다. 초기화가 확인되지 않으면 신규 등록을 보류합니다. 실행 중인 이전 작업이 있으면 HTTP 409로 보류하고, 성공하면 작업·작업 로그·이전 취소 ID만 지웁니다. 설정·이벤트·인증·Drive 파일은 이 API에서 삭제하지 않습니다. 같은 세션의 재요청은 이미 접수된 작업이 있어도 삭제 없이 성공합니다.

신규 작업의 `job_id`는 `<session_id>-...` 형태이며 Feeder가 생성합니다. 워커는 현재 활성 세션과 작업 ID 접두부가 일치하는 요청만 받으므로, 이전 FF 실행의 지연된 제출과 이전 ID 재사용은 거부됩니다. 워커 서비스만 재시작하거나 자동 업데이트할 때는 세션이나 작업 기록을 초기화하지 않습니다. 기존 DB의 구형 컬럼과 NULL 옵션 기록은 조회·취소·정산용으로 읽을 수 있으며, 옛 옵션을 복원해 실행하지 않습니다.

워커 0.13.0부터 SQLite는 세션별 임시 실행 큐로 사용합니다. Feeder가 결과·사용량·복구 체크포인트를 DB에 저장한 뒤 `POST /api/v1/jobs/<job_id>/ack`에 `session_id`를 보내면 해당 terminal 작업과 로그만 삭제합니다. `queued/running`은 승인할 수 없으며, 통신 장애 중인 종료 결과를 시간만으로 지우지 않습니다. 설정·인증·SSE 이벤트의 기존 제한은 유지합니다.

승인 뒤 같은 ID로 다시 접수되지 않게 기존 ID-only 차단 마커를 현재 세션 동안 유지합니다. ACK 재요청은 이미 정리·차단된 ID면 삭제 없는 성공이며, 미확인 ID는 404입니다. 이 응답이 원격 파일의 전송 완료를 새로 판정하는 것은 아닙니다. 마커는 다음 FF 세션 초기화에서 지웁니다. Feeder의 ACK 실패는 복사를 되돌리지 않으며 기존 재시도 또는 다음 세션 초기화로 잔여 결과를 정리합니다. 세션 초기화는 완료 이력을 모두 열거하지 않고 Feeder의 참조 ID와 `queued/running` 목록만 확인합니다. 별도의 세션 누적 전송 한도는 없습니다.

미완료 복사는 이전 작업의 종료 확인·정산 후 검증된 임시 폴더만 정리하여 새 ID와 현재 설정으로 전송합니다. 사용량이 불명확하면 기존 예약을 보존하며 임의로 0으로 만들지 않습니다. 실제 복사 완료 결과나 `uploaded/shared_incoming/moved` 체크포인트가 있으면 재복사하지 않고 최종 이동만 재개합니다. 중단 예약은 진행 중 복사의 최종 이동·정리까지 마친 뒤 신규 배정만 멈춥니다.
